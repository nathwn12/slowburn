# Minimal/Full UI Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a persisted `ui_mode` setting (`minimal` default) and make the app shell render either the minimal layout or today's full layout, without restarting and without cutting the player.

**Architecture:** The mode is one Rust-owned config field exported to TypeScript by ts-rs, read synchronously on first paint, and consumed as a single conditional in the one shell (`src/routes/__root.tsx`). Minimal drops the `StatusBar` ledger and the `Queue` column; everything else — including every player band — lives inside `NowPlaying` and is untouched by the mode. That is the spec's rule enforced structurally rather than by discipline.

**Tech Stack:** Rust (tauri v2 plugin + sqlx config store), ts-rs type generation, React 19, TanStack Query, StyleX, Vitest, Playwright-style component e2e via `vitest` project `e2e`.

**Spec:** `Q:\PROJECTS\PERSONAL\Slowburn\docs\specs\minimal-mode-and-sorting.md` §3.1–§3.3, §3.4, AC1, AC3.

## Global Constraints

- Offline. No new network code of any kind.
- The app is **never launched** by this plan; verification is tests only. Test config forces muted output.
- `src/generated/typings.ts` is generated by ts-rs — **never hand-edit it**.
- `ui_mode` is a typed enum with `#[serde(rename_all = "lowercase")]`, modelled on `TrackViewDensity`
  (`src-tauri/src/plugins/config.rs:48-54`) — **not** a free `String` like `theme`. A string field
  admits `"Minmal"`; a union does not.
- Default is **minimal**.
- The player is never cut by the mode: no band inside `NowPlaying` may be conditional on `ui_mode`.
- One writer per file. Nothing outside the file lists below.

## Review Focus

The spec fixes what the two modes contain but not these conditions:

1. **First paint.** A mode read that resolves asynchronously would render Full for one frame and
   snap to Minimal. Read it synchronously via `ConfigBridge.getInitial` (`src/lib/bridge-config.ts:15`,
   backed by `window.__MUSEEKS_INITIAL_CONFIG`) so there is no flash.
2. **Missing or unknown value.** A config file written before this field existed, or a database
   whose value is unrecognised, must yield `minimal` — never `undefined` and never a crash.
   A user upgrading in place is the normal case, not an edge case.
3. **Toggling during playback.** Switching modes must not restart the app and must not disturb
   playback position, the A-B region, or burn values.
4. **The settings screen itself.** In minimal mode the settings route must still render — the shell
   already has a separate settings branch (`src/routes/__root.tsx:135-138`) and the mode conditional
   must not swallow it.
5. **The queue's own entry point.** With the `Queue` column hidden, confirm there is still a way to
   reach the queue, or record that there is not. Hiding a surface is a layout decision; hiding the
   only route to it is a functional regression.
