# AIMP UI/UX pattern survey - Lane 1 take-list

- What this is: a ranked short-list of AIMP UI/UX patterns that could be adapted to a Slowburn-native implementation. Behaviour and architecture only.
- Source product: AIMP 5.40.2727 (Delphi/VCL desktop application). Install root: `<AIMP install root>` (real path; the Scoop `current` sibling is a junction). Product/version cross-checked against the live profile `<AIMP install root>\Profile\AIMP.ini` `[System] Version=5400` and `VersionBuild=2727`.
- Date of survey: 2026-10-11.
- Posture: CLEAN-ROOM. This document extracts behaviour and architecture patterns only. No AIMP code, skin, icon, image, language file or verbatim UI string is copied or re-used. AIMP strings appear here only as labelled evidence of what a feature is called or does, never as proposed Slowburn UI copy, and no AIMP layout is proposed for wholesale cloning.
- Banned material excluded by instruction: slow/playback speed-tempo-pitch, reverb, and A-B loop are not considered at all.

## Ranked take-list

### 1. One command registry, three hotkey scopes, explicit collision feedback

- kind: pattern
- provenance: `Langs\english.lng` section `[OptionsFrameHotkeys]` (`C1=Hot keys`, `B10=Default`, `c[0]=Command name`, `c[1]=Local`, `c[2]=Global 1`, `c[3]=Global 2`); `[HotkeysGroups]` (grouped namespaces such as `Player.PlaybackControl`, `Playlist.Search`, `MusicLibrary.Table`); `[AIMP]` `N70=Suspend global hot keys` and paired action+hint keys (`acPlaylistPlayFocusedItem` / `acPlaylistPlayFocusedItem.h`); `[MSG]` `19=This hot key is either invalid or already assigned to another application` and `50=This key is already used!`; `AIMP.ini` `[Global Hotkeys] Suspend=0`.
- what AIMP does: every user action is declared once with a stable id and a localized caption plus a separate hint string (the `.h` twin). The Hotkeys settings page lists commands by category and lets each command carry one local binding and two independent global bindings simultaneously. Two distinct conflict messages exist (`[MSG] 19` "already assigned to another application" versus `[MSG] 50` "already used"), which establishes that a collision is rejected with a message distinguishing a clash with this app from a clash with another application. The strings establish the messages only, not when or how they are presented: rejection at capture time and modal presentation are inference, not evidenced (see UNKNOWN). All global hotkeys can be suspended with one toggle.
- why it is worth taking: this is the spine that makes an application keyboard-first without hard-coding. A single registry lets Slowburn drive a keyboard-shortcut settings screen, a future command palette, tooltips, menu items and accessibility labels from one source, and prevents the usual drift where a shortcut exists but its label does not. The dual global scope plus a suspend toggle is exactly the feature set a desktop player needs (media keys while another app has focus, plus a one-click panic switch).
- Slowburn-native form: add a typed `src/lib/actions.ts` registry of `ActionId -> { handler, category, i18nId }`, where the i18n id is a Lingui message id and the handler is dispatched through the existing bridge layer. Persist bindings in SQLite as rows `(action_id, scope, accelerator)` with `scope in {local, global_primary, global_secondary}`. Do not reuse the Windows registry or VCL shortcuts: register `global_primary`/`global_secondary` through Tauri's global-shortcut plugin, handle `local` in the React tree with a top-level keydown router. Surface a collision badge inline in the settings row (and disable Save), rather than a modal, and offer the same `suspend` toggle as a single persisted boolean. Render it as a Slowburn settings table using the existing button and table primitives, not as an AIMP-style grid.
- risk/effort: medium; the registry and local router are small, the global-shortcut plugin and its permission entries are the main work.

### 2. Play queue and playback history as two different first-class surfaces

- kind: pattern
- provenance: `Langs\english.lng` section `[QueueDialog]` (`Caption=Queue manager`, `CB1=Pause`, `L1=Total time:`) and `[QueueDialog.ListView]` (`c[0]=Number`, `c[1]=File name`, `c[2]=Playlist`, `c[3]=Duration`, `acMoveUp`/`acMoveDown`); `[AIMP]` `acQueueManager=Queue manager`, `acQueueClear=Clear queue`, `acPlaylistAddSelectedToQueue`, `acPlaylistRemoveSelectedFromQueue`, `acPlaylistInsertToQueueBeginning`, `N20=Queue`; `AIMP.ini` `[Playlist.Queue] Enabled=1`; `[AIMPML.Controls] History=Playback History` and `[AIMPML] LastPlayback=Last playback`, `PlaybackCount=Playback count`; `[SearchForm.Table] c[2]=Index in queue`.
- what AIMP does: the play queue is a separate, ordered, user-owned list that is not the playlist. Tracks are explicitly added to it (`add to queue`, `add to queue beginning`, `remove from queue`, `clear queue`) and it has its own manager window with manual `Move up`/`Move down` reordering, a pause control and a total-time readout. Playback history is a different concept entirely: it is a Music Library data source with per-track `Last playback` and `Playback count` statistics. The two are never conflated.
- why it is worth taking: separating "what I have chosen to hear next, in this order" from "what I have heard" removes the single biggest source of confusion in a simple player, where the only list usually doubles as both. It gives Slowburn a clean model: the queue is ephemeral intent, history is durable record.
- Slowburn-native form: two SQLite tables, `queue_item(position, track_id, added_at)` and `history_entry(track_id, played_at, play_count)`. Keep the queue as a Zustand store that is the player's actual source of next-track when non-empty, falling back to the active playlist otherwise. Expose it as a slide-over panel on the player route (TanStack Router search-param for open state, not global state), not as a separate window. Present history as its own route ranked by "recently played" and "most played", driven by the same stats columns. Do not copy AIMP's manager dialog; use Slowburn's existing list and drag primitives.
- risk/effort: medium; the data model is simple, the playback-source resolution and drag-reorder are the delicate parts.

### 3. Dense playlist rows driven by format templates, with grouping that collapses and merges

- kind: pattern
- provenance: `Langs\english.lng` section `[OptionsFramePlaylistView]` (`cbShow2ndLine=Show second line with info`, `cbShowDuration`, `cbShowMarks=Show rating`, `cbShowNumbers=Show track number`, `cbShowSwitches=Show switches column`, `cbGroupMode=Enable groups`, `cbMergeGroups=Merge similar groups automatically`, `cbCollapseUnusedGroups=Collapse unused groups automatically`, `cbAbsoluteNumeration=Absolute Numeration`); `AIMP.ini` `[Playlist.Manager]` (`FormatMainLine=%IF(%Artist,%Artist - %Title,%Title)`, `FormatSecondLine=%FileFormat :: %SampleRate, %BitRate, %FileSize`, `GroupFormatLine=%FileDir`); `[Templates]` macro table with `[Templates.Categories]`; `[Actions]` `QuickSearch=Quick search`, `Tabs.ScrollUp`/`Tabs.ScrollDown`; `internal_options.html` (`AllowIncrementalSearch=0`); `features_audiolibrary.html` (Ctrl-click multi-column sort, Ctrl-click value to group by it, incremental search in every drop-down); `AIMP.ini` `[Search]` field flags and `[Playlist.RecentSearchStrings]`.
- what AIMP does: rows are rendered from user-editable format strings, not from fixed columns, so one row can carry two informational lines and the group header is itself a format string. Groups can be enabled, auto-collapsed when unused, and "similar groups" auto-merged, with an absolute-vs-relative numbering toggle. Search is incremental/type-ahead inside the list, recent search strings are remembered, and sorting/grouping are available from the same Ctrl-modified table gestures as the library.
- why it is worth taking: this is how a list stays readable at library scale without a column-configuration UI. Template strings express "second line shows format, sample rate, bitrate, size" as data, which trivially becomes a settings field and keeps the row renderer generic. Group-by-value with collapse/merge is the highest-value density control and is cheap to add to an existing list.
- Slowburn-native form: render each playlist row via a small template evaluator (`src/lib/row-format.ts`) over a typed track object, with the main and secondary line each mapped to a user-editable template stored in settings. Group headers are computed from a `groupBy` field plus a group template. Do not reproduce AIMP's `%Macro()` function set; expose only the fields Slowburn already models and use Lingui for any label that appears in a template. Implement search-as-you-type as a filter that highlights matches and persists the last N queries, matching Slowburn's URL-state preference rather than a global store.
- risk/effort: medium; the template evaluator and grouping are contained, the multi-line virtualized row is the performance-sensitive part.

### 4. A first-class now-playing overlay with configurable events, position and content

- kind: pattern
- provenance: `Langs\english.lng` section `[InfoBar]` (`GB0=Show information about playing file`, `CB1=At start of playback, during:`, `CB9=Before playback finish, during:`, `CB2=By left|By right|By center`, `CB3=Show at desktop top|Show at desktop bottom`, `CB4=Show album art`, `CB6=Over fullscreen applications if it possible`, `CB7=Apply to background only`, `CB8=Always`, `CB10=Notifications from the app`, `CB0=As Information Bar|As Card`, `M3=Font`, `M4=Text Color`); `AIMP.ini` `[InfoBar]` (`ShowInfoBarOnStartPlayback=1`, `ShowInfoBarOnFinishPlayback=0`, `HideDelayOnStartPlayback=5000`, `HideDelayOnFinishPlayback=5000`, `InfoBarPosition=0`, `InfoBarTransparency=75`, `ShowCover=1`, `TextAlign=2`, `FmtInfoBar`, `FmtInfoBarText`, `InfoBar=Segoe UI,...`); `faq_information_bar.html`.
- what AIMP does: the overlay is a configurable component rather than a fixed toast. It has two visual variants (bar or card), fires on its own events (start of playback, before playback finishes, general app notifications), aligns to a chosen edge (`By left` / `By right` / `By center`), positions at desktop top or bottom, chooses a target screen, has independent opacity for background versus text, optionally shows album art, can draw over fullscreen apps, and takes its text from the same template macros as the playlist.
- why it is worth taking: a player spends most of its life unfocused, so the now-playing notification is one of the few surfaces seen every track. Making its trigger events, position, content and appearance all explicit data gives Slowburn a polished, low-effort differentiator, and the same overlay can carry non-playback notifications.
- Slowburn-native form: a single StyleX `NowPlayingOverlay` React component rendered in a small frameless Tauri window (or an in-window absolute layer when the app is focused), driven by a settings object `{ events: string[], position, variant, showCover, opacity, template }`. Reuse the row-format evaluator from take 3 for its text. Do not replicate AIMP's bar/card skinning or its font-per-line model; use Slowburn tokens and a single card with the app font. Support `over fullscreen` only through the Tauri always-on-top window flag and gate it behind an explicit setting, since it is the one genuinely invasive behaviour.
- risk/effort: low to medium; the component is small, the separate-window and always-on-top behaviour is the only tricky part.

### 5. Per-window placement state with docking and a per-window chrome menu, including a docked mini-player

- kind: pattern
- provenance: `Skins\Default.ini` window blocks `[AIMPMainForm]`, `[TrayControl]`, `[QFI]`, `[DropWheel]`, `[InfoBoxWindow]`, `[VisualizationWindow]`, `[MusicLibraryWindow]`, `[PlaylistWindow]`, each with the same key set `Locked`, `Docked`, `Position`, `StayOnTop`, `DPI`, `ToolbarMode`, `WindowState`, `ScreenSize`, `ScreenIndex`, plus `[AIMPMainForm.Layout.<subcomponent>]` blocks carrying `Visible` and `SizeStored`; `Skins\Bliss 4K.ini` `[PlaylistFrame]`/`[MusicLibraryFrame]`; `Skins\Pandemic.ini` `[EqualizerFrame]`/`[TrayControlFlow]`; `Langs\english.lng` `[Actions]` (`Form.DockTo=Dock`, `Form.DockToEdges=to left screen side|to right screen side|to top screen side|to bottom screen side`, `Form.AutoHide=Mode: floating with auto-hiding`, `Form.Fixed=Mode: fixed`, `Form.Float=Mode: floating`, `Form.LockPlacement=Pin window position`, `Form.StayOnTop`, `Form.Undock=Normal mode`, `Form.Visible=%s - show|%s - hide`, `TCFixFloat=Pin floating bar`); `internal_options.html` (`DockEngineShowFloatArrow`, `DockEngineIgnoreFullScreenApps`); `faq_pls_view.html` (drag to undock, drag to a screen edge to become a desktop-toolbar strip, hover the edge marker to reveal); `[OptionsFrameTray]` (`CB1=Minimize to tray on minimizing the application`, `CB3=Show the Mini Player on minimizing to tray`, `TrayCmd` one/double/middle-click actions) and `[AIMP]` `TrayCotnrol=Show Mini Player`.
- what AIMP does: every window is the same kind of object with persisted geometry, DPI, screen index, locked flag, stay-on-top flag and docked flag, independent of the Main window. A shared chrome menu offers Dock / Dock to screen edge / Float / Fixed / Auto-hide / Pin / Stay on top / Undock. A window can be docked to a screen edge as a desktop-toolbar strip; the cited help topic documents this for the playlist specifically, and states that ordinary reveal requires clicking the edge marker (hover is described separately for the drag-and-drop interaction, not as the reveal gesture). Panel sub-components carry their own persisted visibility and size. The Mini Player (TrayControl) is itself just another one of these windows rather than a special mode.
- why it is worth taking: the single most robust idea here is that window placement and visibility are data, written uniformly for every window, which is what makes multi-window feel predictable instead of fiddly. Even if Slowburn ships only two or three windows, adopting one uniform state record and one shared chrome menu avoids a bespoke code path per window, and the mini-player-as-a-window framing is a cleaner mental model than a "mini mode" boolean.
- Slowburn-native form: one `window_state(label, x, y, w, h, screen_index, stay_on_top, docked, locked, dpi)` table and one `useWindowState(label)` hook that Tauri window creation reads and every move/resize writes. Build a single `WindowChromeMenu` React component offering Pin, Stay on top, Dock to edge, Auto-hide, Float and Show/Hide, reusing Slowburn menu primitives. Ship a compact `MiniPlayer` window as a normal window entry, not a mode. Treat the edge-dock-as-toolbar behaviour as optional and later: it depends on app-bar style APIs and is the least portable part, so implement only a floating, always-on-top mini-player first.
- risk/effort: medium to high; the state model and chrome menu are straightforward, restoring geometry across monitors and DPI changes is the hard part.

Take-list count: 5 entries.

## Considered and rejected

- Windows Explorer shell context menu (6 fixed entries: play, open in new playlist, insert, queue, edit tags, convert, plus a cascade toggle and per-extension filters). Evidence: `%APPDATA%\AIMP\AIMP-ContextMenu.ini` `[Menu]` and `[MenuItem*]`, `faq_explorer_context.html`, `internal_options.html` (`Cascade=0`). Rejected: it requires an OS-level shell extension / registry integration that Tauri does not support in a normal install path, it is invasive to the host, and the use case is largely covered by file associations and drag-and-drop. Not recommended.
- Docked edge-strip (desktop toolbar) windows with hover reveal marks. Evidence: `faq_pls_view.html`, `Skins\Pandemic.ini` `[TrayControlFlow]`, `internal_options.html` (`DockEngineShowFloatArrow`, `DockEngineIgnoreFullScreenApps`). Rejected as a standalone take: it depends on app-bar behaviour, fights the Windows taskbar (acknowledged in `faq_tc_taskbar.html`), and offers little over a floating always-on-top mini-player. Retained only as an optional, deferred part of take 5.
- Taskbar integration (track text in the taskbar, scrolling title, progress overlay, player-state button, progress-bar colour state, indeterminate state for streams). Evidence: `Langs\english.lng` section `[OptionsFrameSystem]` (`CB2`-`CB7`, `L1=Player window should be active`). Rejected for now: it is a Windows-specific shell feature with per-OS divergence and no clean cross-platform Tauri story, and it duplicates the now-playing overlay for very little gain. Revisit only if Slowburn commits to Windows-only.
- Smart playlists / preimage data sources (a playlist that is a live view over the Music Library, folders or another playlist, with one-way synchronisation). Evidence: `Langs\english.lng` `[PlaylistsManagerDialog]` (`lbPreimage`, `lbPreimageNotes`), `[AIMPMLPreimageDialog]`, `[AIMPPlaylistFoldersPreimageDialog]`, `AIMP.ini` `[MusicLibrary]`. Rejected as a UI take: it is a large library subsystem whose visible UI is small, so it belongs in a data-model decision, not this take-list.
- Per-playlist personal-appearance overrides and per-playlist playback mode. Evidence: `faq_playlist_personal_settings.html`, `Langs\english.lng` `[OptionsFramePlaylistBehavior]` (`CB47=Each playlist has its own playback mode`) and `miPersonalSettings=Personal settings`. Rejected as a separate take: it is a refinement of take 3, and making every display option overridable per tab multiplies settings surface for modest benefit. Keep only the grouping/collapse subset.
- Single Playlist Mode and lock-from-changes. Evidence: `[OptionsFramePlaylistBehavior]` (`CB57=Single Playlist Mode`, `CB46=Close playlist by double-click on tab`), `[MSG] 32=Single playlist mode: Couldn't change playlist because it is locked!`, `faq_pls_close.html`. Rejected: both are trivial toggles with no architectural value, and locking a playlist to forbid edits is a niche behaviour.
- Tag editor, audio converter, replay gain, chapter editor and rename templates. Evidence: `Langs\english.lng` sections `[ATEForm]`, `[Converter*]`, `[ATERenameForm]`, `[ATEChapters*]`. Rejected: these belong to separate AIMP utilities, not to a player, and are out of Slowburn scope.
- DSP manager, equalizer presets, cross-mixing, silence remover and the tempo/pitch/speed or reverb surface. Evidence: `Langs\english.lng` `[DSPDialog]`, prior worker `aimp-form-evidence.md`. Rejected and excluded by instruction (banned material).
